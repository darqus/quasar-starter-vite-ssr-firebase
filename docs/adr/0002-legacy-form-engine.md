# ADR 0002: один legacy-движок форм

Статус: **принято**
Дата: 2026-11-03

## Контекст

В проекте одновременно существовали три представления о формах:

- рабочий legacy-движок: `useForm` + `FormFields` + компоненты полей;
- `BaseForm.vue`, который не использовался страницами и не передавал `schema`
  в `useForm`;
- `SchemaForm.vue`, реестр полей и `types/form.schema.ts`, которые не были
  подключены к рабочим формам и не были функциональны.

Документация описывала schema-driven-подход как готовый стандарт, хотя код
страниц его не использовал. Параллельно существовали две ветки правил
валидации (legacy-массивы и zod), а `useForm.errors` никто не рендерил.

Это создавало ложное чувство покрытия и заставляло разработчика выбирать
между тремя «источниками истины».

## Решение

Выбран **вариант B** из плана улучшений:

1. Оставляем один движок: `useForm` + `FormFields`.
2. Удаляем `BaseForm`, `SchemaForm`, реестр полей, boot-регистрацию,
   `types/form.schema.ts`, `schemas/`, `types/form-dto.ts`.
3. Удаляем неиспользуемые legacy-массивы правил; `MESSAGES` и `REGEXP`
   остаются как словарь для zod-хелперов.
4. Zod — единственный источник валидации:
   - правила полей генерируются из zod (`rulesFromZodField`);
   - форма целиком валидируется той же схемой (`parseAndCollectErrors`);
   - `useForm.errors` рендерится под полями через `FormFields`.
5. `useForm.validate()` при наличии `schema` не вызывает `QForm.validate()`,
   чтобы не выполнять одну проверку дважды.

## Последствия

- В `src/` остался ровно один механизм форм и один механизм валидации.
- Новые формы добавляются через фабрики полей и zod-схему, без реестров.
- Schema-driven-рендер, динамические массивы полей и field registry не
  поддерживаются. Если они понадобятся, это будет отдельный ADR с миграцией
  всех форм и тестами, а не «ещё один движок рядом».
- Документация по формам сведена в `docs/forms.md`; устаревшие
  `forms-architecture.md` и `forms-advanced-architecture.md` удалены.
